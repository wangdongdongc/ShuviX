---
shuvix: policy v1
shuvix-builtin: true
name: protect-bot-notes
shuvix-displayName: エージェントが bot 定義を変更する前に必ず確認
description: bot 定義ファイルへの書き込みは常に確認します — 自動許可スイッチでも省略されません。
shuvix-policy-scope:
  subject.kind: [agent]
  object.type: [path]
  env.host: [desktop]
shuvix-policy-rules:
  - effect: force-ask
    action: [write]
    match: inDir(object.path, [vars.botsDir])
    prompt: >-
      この書き込みは bot の定義ファイル — そのペルソナとノート — に対するものです。
      diff を確認してください。区切り線より上はあなたが書いたものであり、bot が自分の
      ペルソナを書き換えることはノートの整理には含まれません。
---

**何をするか**：bots ディレクトリ配下へのファイル書き込みは必ず確認し、**自動許可を
有効にしていても確認し続けます**。

**なぜ拒否ではないのか**：bot は markdown ファイルであり、「bot の草案を書いて」と
頼むのは正当な使い方です。一律に拒否すればそれも塞いでしまいます。確認にしておけば
その道を残したまま、自分のファイルの書き換えが画面の外で起きることを防げます。

**なぜ自動許可より強いのか**：これはエージェントが**自分自身について**編集する唯一の
ファイルです。ノート段階はスロットリングされ、会話が終わってからずっと後に動きます
—— そのときあなたは見ていません。ファイル全体を書き直してノートの半分を落とす、
あるいは区切り線より上のペルソナに手を入れる。それこそがこのカードで止めたいものです。

**やらないこと**：

- ファイルツールのみを対象とします。コマンドを実行できるエージェントはここを通らずに
  書き込めます —— 最終的な砦は監査記録と、これらのファイルが設定画面から見えることです。
- 読み取りは対象外です。bot ファイルはプロンプトそのものであり、その本文はすでに
  コンテキストに入っています。

**調整するには**：上書きコピーを作って編集してください。信頼できるようになったら
`subject.profile == 'bot-notes'` でノート段階を除外するのは妥当な変更です —— それは
あなた自身のファイルについての判断です。
