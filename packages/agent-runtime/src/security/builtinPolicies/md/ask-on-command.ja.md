---
shuvix: policy v1
shuvix-builtin: true
name: ask-on-command
shuvix-displayName: 制限なしのコマンド実行前に確認
description: サンドボックスに閉じ込められていない bash / PowerShell / ssh コマンドはコマンドごとにユーザー確認が必要。閉じ込められたコマンドはそのまま実行される。
shuvix-policy-scope:
  subject.kind: [agent]
  object.type: [command]
shuvix-policy-rules:
  - effect: ask
    action: [execute]
    match: '!has(object.sandboxed) || !object.sandboxed'
    prompt: このコマンドは制限されていない。許可するとあなたのシステム権限で実行され、任意のファイルへのアクセスも通信もできる。実際に何をするか確かめてから許可すること。
---

**このポリシーの役割**：あなたの全権限で動くことになるコマンドは、先に確認する。macOS で
サンドボックスがオン（設定 → LLM ツール → bash）のとき、コマンドは既定でサンドボックス内で
動く —— 読み書きできるのはこのセッション自身のディレクトリ（作業ディレクトリ、その一時フォルダ、
artifacts とツール結果、そして「許可して記憶」したパス）だけで、ホームフォルダの外のシステムの
場所は読め、ネットワークも使える —— ので確認なしで実行される。確認が出るのは：

- エージェントがサンドボックスの外で実行したコマンド（`dangerouslyDisableSandbox`）。
  サンドボックスはプロジェクト内の簡単な作業のためのもので、git、依存のインストール、
  ホームフォルダの設定やキャッシュを読むビルドやツール、docker、`open`、`sudo` などは
  初めから外で実行し、ここに来ることが想定されている；
- サンドボックスがオフ、またはこのコンピュータで使えないとき（現時点では Windows と Linux、
  あるいは ShuviX 自体が別のサンドボックス内で動いている場合）のすべてのコマンド；
- すべての ssh コマンド —— リモートのマシンで動くため、ローカルのサンドボックスは届かない。

確認するかどうかは、ホストがこの実行について報告する `sandboxed` 属性で決まり、コマンドの
文面からは判断しない。

**ファイルの境界のほかに、制限付きコマンドを外に出さないもの**：アプリを開く、Apple Events を
送る、ジョブを登録する（`open`、`osascript`、`launchctl`）ことはできず、シグナルを送れるのは
自分が起動したプロセスだけで、接続できるのは ShuviX 自身のコマンドライン用ソケットと DNS
だけ、他のローカルサービス（Docker、ssh-agent など）には繋がらない。これらがなければ、
一つのコマンドがサンドボックスの外で何かを起動でき、ファイルの境界は意味を失う。

**カバーしないこと**：

- 確認がゲート：制限なしのコマンドを許可した瞬間、それはあなたのシステム権限で実行される。
- 制限付きのコマンドでも作業ディレクトリ内のものは何でも変更できる。そこにある git 自身の
  ファイルも含む。
- 必ずあなたに届くとは限らない：自動レビューがオンのときは、レビューする
  エージェントが先に答える —— 普段の作業は通し、明らかに有害なものは拒否し、
  残りは意見を添えてあなたに回す。

**調整するには**：上書きコピーを作成して編集する。`match` の行を消すと、制限の有無に
かかわらず全コマンドで確認が出る状態に戻る。
