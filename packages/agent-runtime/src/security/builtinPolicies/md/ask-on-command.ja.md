---
shuvix: policy v1
shuvix-builtin: true
name: ask-on-command
shuvix-displayName: 制限なしのコマンド実行前に確認
description: サンドボックスに閉じ込められていない bash / PowerShell / ssh コマンドはコマンドごとにユーザー確認が必要。閉じ込められたコマンドはそのまま実行される。
shuvix-policy-scope:
  subject.kind: [agent]
  object.type: [command]
shuvix-policy-rules:
  - effect: ask
    action: [execute]
    match: '!has(object.sandboxed) || !object.sandboxed'
    prompt: このコマンドは制限されていない。許可するとあなたのシステム権限で実行され、任意のファイルへのアクセスも通信もできる。実際に何をするか確かめてから許可すること。
---

**このポリシーの役割**：あなたの全権限で動くコマンドは、事前にあなたへの確認が必要に
なる。macOS でサンドボックスがオンのとき（設定 → LLM ツール → bash）、通常のコマンドは
制限付きで実行される——ファイルを変更できるのはプロジェクト、一時フォルダ、ツールの
キャッシュの中だけで、認証情報や個人フォルダは読めない——ので、確認なしで実行される。
それでも確認が出るのは：

- 制限付きでは動かないため、エージェントが明示的にフルアクセスを求めたコマンド
  （アプリを開く、`osascript`、docker、`sudo`、git リポジトリの新規作成、プライベートな
  リモートへの push など）；
- サンドボックスがオフ、またはこのコンピュータで使えないときの全コマンド（現時点の
  Windows と Linux、または ShuviX 自身が別のサンドボックス内で動いている場合）；
- すべての ssh コマンド——リモートのマシンで動くので、ローカルのサンドボックスは届かない。

確認するかどうかは、ホストがこの実行について報告する `sandboxed` 属性で決まり、コマンド
の見た目では決まらない。

**カバーしないこと**：

- 確認がゲート：制限なしのコマンドを許可した瞬間、それはあなたのシステム権限で実行される。
- 制限付きのコマンドでもプロジェクト内のものは何でも変更できる——プロジェクトごと削除
  することもサンドボックスの範囲内。block-catastrophic-commands は、マシンを壊す少数の
  コマンドをどちらの場合も拒否する。
- 必ずあなたに届くとは限らない：自動レビューがオンのときは、レビューする
  エージェントが先に答える —— 普段の作業は通し、明らかに有害なものは拒否し、
  残りは意見を添えてあなたに回す。
- 自動許可のスイッチをオンにすると、別の組み込みポリシー session-grants が効いて確認は
  スキップされる。フルアクセスを求めるコマンドも同様。

**調整するには**：上書きコピーを作成して編集する。`match` の行を消すと、制限の有無に
かかわらず全コマンドで確認が出る状態に戻る。
