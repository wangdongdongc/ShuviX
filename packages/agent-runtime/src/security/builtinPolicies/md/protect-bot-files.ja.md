---
shuvix: policy v1
shuvix-builtin: true
name: protect-bot-files
shuvix-displayName: エージェントが bot 定義を変更する前に必ず確認
description: bot 定義ファイルへの書き込みは常に確認します — 自動許可スイッチでも省略されません。
shuvix-policy-scope:
  subject.kind: [agent]
  object.type: [path]
  env.host: [desktop]
shuvix-policy-rules:
  - effect: force-ask
    action: [write]
    match: inDir(object.path, [vars.botsDir])
    prompt: >-
      この書き込みは bot の定義ファイル — そのペルソナと記憶 — に対するものです。以後、
      その bot のために動くすべてのエージェントが、これをシステムプロンプトの一部として
      読み込みます。diff を確認してください。新しい好みや事実を書き足すのはこのファイルの
      用途そのものですが、ペルソナの書き換えは「この bot が誰か」の変更です。
---

**何をするか**：bots ディレクトリ配下へのファイル書き込みは必ず確認し、**自動許可を
有効にしていても確認し続けます**。

**なぜ拒否ではないのか**：bot は markdown ファイルであり、「bot の草案を書いて」と
頼むのは正当な使い方です。一律に拒否すればそれも塞いでしまいます。確認にしておけば
その道を残したまま、自分のファイルの書き換えが画面の外で起きることを防げます。

**なぜ自動許可より強いのか**：bot のファイルは、エージェントが**自分自身について**
編集する唯一のファイルです。その本文はその bot のために動くすべてのエージェントの
システムプロンプト末尾に付加され、bot は自らそれを最新に保つことを求められます ——
明言された好み、訂正、プロジェクトについての事実。その編集はあなたへの返答の途中で
起き、以後のすべての会話に引き継がれます。ペルソナを静かに書き換える、あるいは知って
いたことの半分を落とす編集こそ、このカードで止めたいものです。

**やらないこと**：

- ファイルツールのみを対象とします。コマンドを実行できるエージェントはここを通らずに
  書き込めます —— 最終的な砦は監査記録と、これらのファイルが設定画面から見えることです。
- 読み取りは対象外です。bot の本文はすでにエージェントのシステムプロンプトにあり、
  ホストは派遣時にこのファイルを既読として記録するため、自己編集に先立つ `read` は
  不要です。

**調整するには**：上書きコピーを作って編集してください。信頼できるようになったら
`subject.profile == '<agent 名>'` で特定のタスク段エージェントを緩めるのは妥当な
変更です —— それはあなた自身のファイルについての判断です。
