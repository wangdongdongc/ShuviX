---
shuvix: policy v1
shuvix-id: policy:builtin:ask-on-session-access
shuvix-builtin: true
name: ask-on-session-access
shuvix-displayName: 別のセッションを使う前に確認
description: エージェントは自分のサブセッションと、このセッションの権限表にあるセッションは自由に使える。それ以外のセッションを見る・話しかけるときは先に確認する。
shuvix-policy-scope:
  subject.kind: [agent]
  object.type: [session]
  env.host: [desktop]
shuvix-policy-rules:
  - effect: ask
    action: [read]
    match: >-
      !object.ownTurn
      && !(object.sessionId in vars.aclSessionRead)
    prompt: 別のセッションの会話 —— その回答としたこと —— をこのセッションに持ち込む。そのセッションは別のプロジェクトのものかもしれない。
  - effect: ask
    action: [write]
    match: >-
      !object.ownTurn
      && !(object.sessionId in vars.aclSessionWrite)
    prompt: 別のセッションにメッセージを送る。そのセッションは自分のフォルダと自分の権限表で作業する。許可する前にメッセージを確認すること。
---

**このポリシーの役割**：エージェントは `session` ツールで別のセッションとやり取りできる —— 入力欄でセッションを
@ すると、エージェントはその id でそのセッションを指せる。次のものは確認なしで使える：

- **自分のサブセッション** —— 自分で開いたもの；
- **別のセッションで自分が始めたターン**：そのターンの回答を受け取る、そのターンの質問に答える、割り込む、
  止める —— ターンを始めた時点でこのポリシーを通っている；
- **このセッションの権限表にあるセッション** —— 確認カードで「許可して記憶」するとそこに 1 行書かれる。
  1 行は**閲覧**（回答を読む、中で何が起きたかを見る、待つ）か**対話**（メッセージを送る、割り込む、質問に
  答える、自分が始めたターンを止める —— 対話は閲覧を含む）のどちらか。

それ以外は**すべて確認する**：別のセッションを見ること、そこへ送るメッセージ 1 通ごと。一度だけ許可した
セッションは次回また確認する。記憶すれば確認しなくなる。これらの行はセッション設定にあり、閲覧と対話の切り替えや
削除ができる。

**確認する理由**：別のセッションには自分の作業フォルダと自分の権限表がある —— 多くは別のプロジェクト。
エージェントにそれと話させるのは、そのセッションが届くものすべてにエージェントを届かせることになり、
見ればその会話がこのセッションに移ってくる。

**このポリシーがしないこと**：

- 自動レビューはこの確認に答えない：組み込みの hook `auto-review` はセッションへのアクセスをあなたに任せるので、
  カードはすべてあなたに届く。
- メッセージを受け取った後のそのセッションの動きは縛らない —— そのセッション自身のポリシーと権限表が決める。
  あなたがそこで直接入力するのと同じ。
- 許可は 1 つのセッションのもの。サブセッションは作成時に親の許可を、fork は元のセッションの許可をコピーする。

**調整するには**：上書きコピーを作って編集する。閲覧のルールを消すと、エージェントは id さえ分かればどのセッションも
確認なしで見られる。
