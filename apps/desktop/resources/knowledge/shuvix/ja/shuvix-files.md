# ShuviX のカスタマイズファイル

ShuviX は **`~/.shuvix/` 配下の markdown ファイル**でカスタマイズします。作るべきデータベース行も
「有効化」スイッチも再起動もありません：**存在して、かつ解析が通るファイルは、次に使われた時点で
有効**です。この一篇は地図です。ファイル種別ごとに、このナレッジベースに一篇ずつ、キー単位の完全な
仕様があります。

## ディレクトリ地図

| 何か                                                          | 置き場所                                                                       | マーカー行               | エントリ          |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------ | ----------------- |
| **Agent** —— エージェントが動く人格 + ツールのホワイトリスト   | `~/.shuvix/agents/<name>.md`                                                   | `shuvix: agent v1`       | `agent-md`        |
| **Bot** —— bot チャットに結び付いた人格 + 記憶                 | `~/.shuvix/bots/<name>.md`                                                     | `shuvix: bot v2`         | `bot-md`          |
| **セキュリティポリシー** —— ツール呼び出しを許可・確認・拒否   | `~/.shuvix/policies/<name>.md`                                                 | `shuvix: policy v1`      | `policy-md`       |
| **Hook** —— セッションイベントでエージェントを派遣             | `~/.shuvix/hooks/<name>.md`                                                    | `shuvix: hook v1`        | `hook-md`         |
| **ナレッジエントリ** —— ユーザーのナレッジベース内の一つのノート | `~/.shuvix/knowledge/<base>/**/*.md`                                           | `shuvix: okf v0.2`       | `knowledge-entry` |
| **Skill** —— 再利用できる指示パック（Agent Skills 形式）       | `~/.shuvix/skills/<name>/SKILL.md`、`<project>/.claude/skills/<name>/SKILL.md` | なし（`name:` が必須）   | `skills`          |

`~/.shuvix/` 配下のそれ以外は ShuviX 自身のもので、手で編集する場所ではありません：`knowledge-shuvix/`
（ShuviX が維持するナレッジバンドル、プロジェクトごとに一つ —— `knowledge` ツール経由で書かれる）、
`skills/.config.json`（無効化した skill と登録した追加 skill ディレクトリ）、`widgets/`、`tts/`、
`cli-token`。古い `memory/`、`wikis/`、`workflows/` は廃止された形式で、もう読まれません。

**組み込みはアプリの中にあり、ディスク上にはありません。** ShuviX は組み込みエージェント（`work`、
`chat`、`notebook`、`bot`、`coding`、`explore`、`widget`、`titler`、`knowledge-writer`）、組み込みセキュリティポリシー、そして一つの組み込み hook
（`auto-title`）を同梱しています。組み込みの bot と skill はありません。組み込みは編集できませんが
**上書き**できます：`name` が組み込みと同じユーザーファイルは、それを丸ごと置き換えます（設定の各タブに
「上書きコピーを作成」があり、組み込みの現在のテキストを出発点としてあなたのディレクトリに書き出します）。

## `shuvix:` マーカー

すべての ShuviX 契約ファイルは YAML frontmatter で始まり、その**最初のキー**がファイル種別マーカーです：

```yaml
---
shuvix: agent v1
name: scout
---
```

値は `<type> v<version>` です。type はそのファイルが何か（`agent`、`bot`、`policy`、`hook`、ナレッジ
エントリは `okf`）、version はその形式自身の改訂番号（`v1`、`v2`）、ナレッジエントリでは準拠する OKF
仕様のバージョン（`v0.2`）です。パーサーは **type だけ**で判別し、version の欠落や新しい値は許容します。

マーカーがどれほど厳しく要求されるかは種別ごとに違います —— 正確な規則は各エントリにあります：

- **agent、policy、ナレッジエントリ**：読み取り時は省略可（手書きで欠けていても読み込まれる）。
  ShuviX がこの種のファイルを書くときは必ず付けます。
- **bot**：省略可ですが、**種別が違えば拒否**されます —— `bots/` に落ちた agent ファイルは人格として
  読まれるのではなく拒否されます。
- **hook**：**必須** —— これがないファイルは hook ではありません。

すべての種別に共通する関連規則：

- frontmatter は**ファイルの先頭**になければなりません（BOM と先頭の空行は許容）。`---` の行で囲みます。
  中身は本物の YAML で、完全な YAML パーサーで読まれます —— 引用符、複数行文字列、コメントが使えます。
  本文の途中に現れる `---` ブロックは本文です。
- `name` の既定値は**ファイルのベース名**（`scout.md` → `scout`）で、frontmatter で上書きできます。
  `shuvix-displayName` は UI に表示する人間向けのラベルです。
- ShuviX 独自のキーには `shuvix-` の接頭辞が付きます（例：`shuvix-tools`、`shuvix-policy-rules`、
  `shuvix-hook-on`）。接頭辞は意図的なものです：同じ markdown を別のアプリケーションが開いたとき、
  `tools` のような汎用キーを誤読してはならないからです。接頭辞のない未知のキーは無視されます。未知の
  `shuvix-` キーの扱いは種別によります（hook は拒否します）。
- `shuvix-builtin: true` は ShuviX が同梱するファイルに現れます。パーサーは読みません。「このテキストは
  組み込みセットのもの」と述べるだけです。ユーザーファイルに加えないでください —— 何もしません。

## 不正なファイルは丸ごと拒否

agent、bot、policy、hook の四つのパーサーは一つの哲学を共有します：構造的に不正なファイル
（frontmatter がない、YAML エラー、frontmatter がマッピングでない、キーの型違い、決して一致しない規則
……）は**丸ごと拒否され、半分だけ適用されることはありません**。拒否されたユーザーファイルは：

- ランタイムからスキップされます —— 同名の組み込みを隠すことはありません；
- 対応する設定タブの「解析できません」の下に、パーサーの理由と共に一覧されます（サイドバーの Bots
  グループも不正な bot ファイルを同様に表示します）；
- 編集中のノートブックのプロパティカードに、同じ判定がリアルタイムで表示されます。

ナレッジエントリは意図的な例外です（「広く読み、厳しく書く」）：有効な OKF 概念でないノートも、
ノートであることに変わりはありません —— `knowledge-entry` を参照。

## 同名の上書き

複数のファイルが同じ `name` を持つとき、ちょうど一つが有効で、残りは**上書き済み**として一覧されます
（黙ってスキップされることはありません）：

1. ユーザーファイルが組み込みに勝つ；
2. ユーザーファイル同士では、**ファイル名がその名前そのもの**であるものが勝つ（`scout.md` は
   `scout copy.md` に勝つ；ファイル名は、新規ファイルが受ける同じ正規化 —— `\ / : * ? " < > |` は `-`
   に、先頭のドットは除去 —— の後、大文字小文字を区別せず比較される）；
3. 次に、ファイル名が短いもの；
4. 最後に、ファイル名のコードポイント順（ディレクトリ列挙順は決して使わない）。

ランタイムの有効集合と設定の一覧は、この一つの解決の二つの見え方です。有効と表示されている行が、
実際に使われているコピーです。

## 編集と確認

ShuviX でこれらのファイルを開くと、**ノートブックセッション**として開きます：ライブプレビューの
markdown エディタで、frontmatter にはプロパティカード（既知のキーにはドロップダウンとピッカー、
パーサーの判定はバッジ）が付き、自動保存されます。別のエディタも保存ボタンもありません。ディスク上の
ファイルが唯一の真実で、どのエディタで変更しても次の使用時に読み込まれます。

ユーザーに代わってこれらのファイルを作成・変更するときは：

- 上の表の正確なパスに、`write` ツールでファイル全体を書きます（既存ファイルは `edit`）。ディレクトリが
  まだ無いかもしれません —— 作成してください。上書きのひな型には、組み込みの現在のテキスト（設定の
  「上書きコピーを作成」、または本ベースの各エントリで引用している組み込み `md`）を使います。
- `shuvix:` マーカーを持つファイルへの `write` / `edit` の結果には、パーサーの判定が付いて返ってきます
  （ファイル自体は書かれています —— 判定は受領票であり、関門ではありません）。それを読んでファイルを
  直してください。成功を報告するのではなく。
- ファイルがどこに現れるかをユーザーに示します：設定 → Agent / ポリシー / Hook、サイドバーの Bots
  グループ、ナレッジベースグループ、または Skills タブ。
