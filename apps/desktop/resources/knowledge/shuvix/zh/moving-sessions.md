# 把会话搬进另一个项目

一条会话属于一个项目（或者不属于任何项目）。ShuviX 没有把会话搬到别的项目的按钮，也没有子项目。
会话由 agent 来搬，而且总是**拉过来**：目标项目里一条会话的 agent，把别的项目的会话搬进自己所在的项目。
项目太大了要拆，用的也是这个办法。

## 用户怎么做

1. 照常新建一个项目。它可以和原项目指向同一个目录（按主题拆），也可以指向别的目录，比如子目录（按模块拆）。
2. 在**新**项目里开一条会话。
3. 输入 `@`，选中要搬过来的会话 —— 列表里是所有项目的会话 —— 让 agent 把它们搬过来。
4. 在确认卡上点允许。卡上列着这次要搬的每一条会话和它原来的项目。

搬过来的会话连同它们的子会话，之后出现在新项目下面。

## agent 怎么做

调 `session` 工具，动作 `move-session`，`session_ids` 填用户 @ 出来的 id
（`[session: id <id> — "<title>"]`），原样照抄。没有“目标项目”这个参数 —— 目标就是发起调用的那条会话
所在的项目。所以 agent 不能把会话搬到别处，不能搬自己这一条；不在项目里的会话什么都搬不了。

一次调用只出**一张**卡，列出点名的全部会话（最多 50 条）。只有用户能回答，也不能记住：允许 agent 查看
或对话一条会话的那一行，不等于同意把它搬走。搬动不读那些会话里的任何内容。

## 哪些搬不了

| 会话                                             | 原因                                         |
| ------------------------------------------------ | -------------------------------------------- |
| 子会话                                           | 搬它的父会话，子会话跟着走                   |
| bot 会话                                         | 它属于它的 bot，不属于项目                   |
| 不属于任何项目的对话、浏览器标签页会话           | 只能搬别的项目里的会话                       |
| 知识库条目、agent、bot、策略等文件的笔记本       | 它绑在那份文件上                             |
| 正在一轮当中的会话，或有子会话正在跑的会话       | 一轮当中会换目录；等这一轮结束再搬           |
| 本项目里已经有同一份文件的笔记本的笔记本会话     | 一份文件只有一条笔记本会话                   |

结果里逐条写明没搬的会话和原因。fork 出来的是独立的会话：没被点名就留在原处。

## 搬过来的会话有什么变化

- 从此在本项目里工作：本项目的目录、环境变量、项目提示词和项目知识库。新项目没有定义的环境变量就没有了，
  所以先把新项目配好。
- 会话自己选的东西保留：它的 MCP 服务器、知识库勾选，以及权限表里授予过的路径和会话。
- 两个项目目录不同时，会话的系统提示词会重建，下一条消息就从本项目出发。目录相同则不重建；项目提示词或
  知识库不同时，会话照常提示“系统提示词已过时”，重建与否由用户决定。
- 对话本身不动。里面写过的路径还指着原来的地方。

知识库条目不随它搬：原项目的条目留在原项目的知识库里。
