# Hook 文件

一份 **hook** 只说一件事：*在这些触发点上、当这个条件成立时，派发这个 agent，并把这段话交给它*。
ShuviX 把事件附在那段话后面，agent 用自己的工具做事，**宿主从不读 agent 的结果** —— hook 是观察者，
不是拦截者。它拦不住、改不了、也拖不慢触发它的那件事。

- 位置：`~/.shuvix/hooks/<name>.md`。
- 标记：`shuvix: hook v1` —— **必需**（不存在标记引入之前的 hook 文件，没有它的只可能是误投的笔记）。
  `hook` 与 `hook v2` 也认；版本不检查。
- 存在即生效，每次触发时重新读取。一个内置：`auto-title`。

## 示例

```markdown
---
shuvix: hook v1
name: capture-decisions
description: After each turn in a project session, keep any decision worth keeping.
shuvix-hook-agent: knowledge-writer
shuvix-hook-on:
  - trigger: session.turn-completed
    when: event.profileName == 'work' && event.textMessageCount >= 2
---

Read `recentText` in the event below. If it holds a decision about this project, record it
in the `project` knowledge base. Otherwise finish without writing.
```

## frontmatter 键

| 键                    | 类型       | 必填   | 含义                                                                                                                                                        |
| --------------------- | ---------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `shuvix`              | `hook v1`  | **是** | 文件类型标记。                                                                                                                                              |
| `name`                | 字符串     | 否     | 身份；缺省取文件基础名。                                                                                                                                    |
| `shuvix-displayName`  | 字符串     | 否     | 设置 → Hook 里的标签。缺省 = `name`。                                                                                                                       |
| `description`         | 字符串     | 否     | 设置列表里的一句话。                                                                                                                                        |
| `shuvix-hook-agent`   | 字符串     | **是** | 要派发的 agent，按 `name`：任何内置 agent 或 `~/.shuvix/agents/<name>.md`。**绝不能是基座人格**（`work` / `chat` / `notebook` / `bot`）—— 解析时拒绝。       |
| `shuvix-hook-on`      | 绑定列表   | **是** | 至少一条 `{ trigger, when? }`。`trigger` 是触发点 id；`when` 是可选的 CEL 表达式。绑定里出现别的键即拒绝。                                                    |

严格性（整份拒绝，原因显示在设置 → Hook）：缺标记、`shuvix-hook-agent` 缺失或为空、agent 是基座人格、
`shuvix-hook-on` 缺失 / 为空 / 不是列表、某条绑定没有 `trigger` 或带了多余的键、`when` 不是字符串或
不是合法 CEL、裸的 `on:` / `agent:` 键（只读带前缀的名字 —— 写错的键名不能静默变成「没有绑定」），
以及任何不是上述两个的 `shuvix-hook-*` 键。**未知的触发点 id 不算错**：绑定保留但惰性化，并记一条警告，
因为触发点词汇表随版本增长。`when` 留空或写 `~` 表示「没有条件」。

## 正文 —— 任务文本

frontmatter 之后的全部内容就是交给 agent 的那段话。可以为空（agent 自己的文件已经说清要做什么时）。
**没有模板语法**：没有占位符，没有变量。事件由运行时以 YAML 附在一个固定围栏里：

```text
<body>

<hook_event trigger="session.turn-completed">
sessionId: …
profileName: work
title: …
isDefaultTitle: false
turnCount: 3
textMessageCount: 5
titleAutoGenerated: true
recentText: |
  User: …
  Assistant: …
</hook_event>
```

想让 agent 只看某个字段，在正文里点名它（「摘录在 `recentText` 里」）。

## 触发点

现有的两个触发点都是**会话域**的，由普通聊天会话发出（笔记本会话不发）。载荷只放发出方天然持有的事实：

| 触发点                     | 何时                                                                                       | 载荷                                                                                                                                                                                                                     |
| -------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `session.prompt-accepted`  | 一条用户 prompt 通过校验、即将交给根 agent（模型尚未开始）                                  | `sessionId`、`profileName`（`work` / `chat` / `bot`，或子会话钉下的 agent）、`title`、`isDefaultTitle`（标题仍是通用缺省值）、`promptText`                                                                                 |
| `session.turn-completed`   | 一整轮结束，含工具调用 —— **成功、失败或被中止都触发**                                       | 上述四个公共字段，加 `turnCount`（至今的用户文本消息数，含本轮）、`textMessageCount`（非空的用户 + 助手消息数）、`titleAutoGenerated`（标题仍出自自动化时为 `true`）、`recentText`（对话尾部，约 1000 字）                       |

新增触发点是 ShuviX 的改动（触发点表加一行、业务处加一个 emit）；hook 自己发明不出来。

## `when` 过滤

CEL（Common Expression Language —— 与安全策略同一个引擎，但没有 `inDir` 那类策略函数）。它必须在下面
的上下文上求值为**布尔**：

- `event` —— 上面的载荷**加上** `trigger`（触发点 id；因此 `trigger` 是保留的载荷键）；
- `env` —— `{ host: 'desktop' | 'extension', platform: 'darwin' | 'win32' | 'linux' }`。

读取载荷里没有的字段是错误，而错误意味着**不命中**（外加一条警告）—— hook 绝不会误触发。可选字段
用 `has(event.field)` 守住。

## 运行时规则（宿主侧，不在文件里）

- 一次运行 = 在**发出事件的那条会话之下**派发一次点名的 agent —— 与 `agent` 工具同一条路，所以工具、
  询问、LLM 日志与子代理面板都落在那条会话上，每次工具调用都过同一套安全策略。模型 = 会话当前的模型，
  除非 agent 文件的 `shuvix-model` 另有声明；hook 自己从不选模型。
- **去重**：这个 hook 在这条会话上的上一次还没跑完时，新的触发被跳过（`busy`）。**超时**：5 分钟，
  到点中止。**未知 agent / 没有可用模型**：跳过并记日志（配置错误，不算失败的运行）。
- agent 的回答被丢弃。它要留下的任何东西都得经自己的工具去做（记进知识库、用 `session` 工具设标题……）。
- 运行在归属会话的子代理面板与主进程日志里可见（`hook "<name>" run=… start / ok / failed`、
  `skipped …: busy | unknown-agent | no-model`）。没有日志文件。
- 删除会话会中止它的 hook 运行。

## 内置 hook 与覆盖

`auto-title` 在 `session.prompt-accepted when event.isDefaultTitle` 与 `session.turn-completed when
event.titleAutoGenerated && event.turnCount == 2 && event.textMessageCount >= 3` 上点名 `titler`
agent；titler 用 `session` 工具的 `set-title` 应用标题。一份名为 `auto-title` 的用户文件整个取代它
（想关掉它，一条带 `when: false` 绑定的覆盖就够了）。同名副本按 `shuvix-files` 条目里的规则处理。

## 刻意没有的

没有脚本块、没有编排原语、没有结果 schema、没有提示词模板、没有并发或超时键、没有日志文件，也没有
同步或阻塞式 hook。如果一件事需要*改变*会话接下来做什么，它就不是 hook —— 它属于 agent 自己的提示词，
或一条安全策略。
