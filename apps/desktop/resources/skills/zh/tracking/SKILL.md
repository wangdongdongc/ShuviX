# 跟踪项

跟踪项记的是**用户自己觉得还没完**、过几天还要再看一眼的事：没修完的 bug、在等别人回复、还没定下来的决定。一件事一份 md，放在 `~/.shuvix/tracking/`，用户在侧栏 Library 的「跟踪项」里看它们。

它是用户的清单，不是会话摘要。大多数会话是已经做完的事，不需要跟踪项；大多数时候，一次整理一项都不用新建。宁可漏掉，也不要替用户多记 —— 用户想跟的事，他会说。

## 去哪里找

只看下面三处，不要去翻 `~/.shuvix` 里别的地方。

- **会话**：用 `session` 工具的 `list-sessions`，`active_since` 取触发事件里 `lastFiredAt` 那一天（没有就取七天前）。跳过标着 `self="true"` 的这一条（就是你现在这次运行）；也跳过 `bot` 和这一条相同、`inputs` 只有 `trigger` 的那些 —— 那是你以前的运行，不是用户的活动。对可能有关的会话用 `read-session` 或 `inspect-session` 看清楚发生了什么。
- **日记**：`~/.shuvix/daily/` 里这段时间的 `YYYY-MM-DD.md`，是用户自己写的当天做了什么。没有就算了。
- **跟踪项目录**：先 `ls ~/.shuvix/tracking/` 看已经有哪些，再读和这次有关的。目录可能还是空的；新建文件直接用 `write`。

## 每件事怎么处理

- **已有的项**：这段时间有新进展就更新（见下面的格式），不用问。
- **直接新建**：只有**用户自己的话**说明这件事还没完的时候 —— 会话里用户写的「回头再看」「等 X 回复」「明天接着弄」「先放着」，或者日记里写的「还没修完」这类。agent 的总结、agent 说的「下一步可以……」都不算。新建时在进展里引用那句原话。
- **提议**：找不到这样的原话，但你确实觉得值得跟的，用 `suggest` 提议，一次至多三条，最值得的在前：
  - `title`：要跟的是哪件事，例如「跟踪：等李回复迁移方案」；
  - `detail`：依据 —— 哪条会话、发生了什么；
  - `message`：用户采纳时对你说的话，例如「建一个跟踪项：等李回复数据库迁移方案」。用户采纳后你会收到这句话，那时再建。
- **不管**：已经做完的事、当天就能做完的待办、只是讨论过的话题、agent 自己提出而用户没接的想法。

## 文件格式

写或改跟踪项之前先读 `references/format.md`：frontmatter、标题、结论与进展怎么写，文件名怎么起。

- 同一件事已经有文件了，就更新那份，不要再建一份。
- 不删除文件；用户让删时再删。

## 整理完怎么回复

一两句说这次更新了哪些项、新建了哪些（带文件名）。提议已经在卡片上，不要在正文里再列一遍。什么都没变，就一句话说这次没有要更新的。
