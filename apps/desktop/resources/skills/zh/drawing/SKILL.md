# 作图手艺

```svg 围栏的**契约**——有哪些 token、什么会被剥掉、`viewBox` 怎么写——已经在你的系统提示里了。**这份技能讲的是手艺**：画什么，以及怎么画才读得懂。

画数据图、流程或结构图，或者任何标记多于寥寥几个的图之前，先加载它。两个框一根箭头的草图用不着。

**框与箭头**（流程、结构、分层、前后对比）有它自己的参考：`references/diagrams.md`。画这类图之前先读它；下面的步骤讲的是承载数据的图。

## 按这个顺序走。颜色排最后。

1. **先判断它该不该是一张图。** 散文常常更清楚，而一个数字不是图表。→ `references/choosing-a-form.md`
2. **按数据的职责选图型**——量级、身份、极性、单个头条数、随时间变化。职责决定图型，这不是品味问题。→ 同一份
3. **摆标记。** 细笔、退让的骨架、用留白而不是描边来分隔。→ `references/marks.md`
4. **按职责分配颜色**（见下）——不按喜好，也不按排名。
5. **拿 `references/anti-patterns.md` 过一遍。** 你的图对上哪一条，它就是错的。这一步的性价比高于本技能里的任何东西，别跳过。
6. **读一遍渲染出来的图。** 标注互相压住、图元跑出 `viewBox`、用图例干了直接标注该干的活——都说明还没画完。

## 颜色：四种职责，四组 token

每一个颜色都只回答其中一种。先定职责，token 自然就定了。

| 颜色的职责 | token | 规矩 |
|---|---|---|
| **身份**——这是哪一条系列 | `--viz-1` … `--viz-8` | 按此顺序取，绝不循环复用 |
| **量级**——有多少 | `--viz-seq-1`（最小）… `--viz-seq-5`（最大） | 一条色阶，单调 |
| **极性**——在「什么都没有」的哪一侧 | `--viz-1` ↔ `--viz-mid` ↔ `--viz-8` | 中间是灰，两极是对立色相 |
| **状态**——好还是坏 | `--viz-good` / `--viz-warn` / `--viz-serious` / `--viz-critical` | 只在颜色**真的表示**一个状态时用。绝不拿来当第 9 条系列 |

骨架与墨不算颜色职责：网格线 `--viz-grid`，坐标轴与基线 `--viz-axis`，一切文字 `--theme-text-primary` / `-secondary` / `-tertiary`。

**槽位顺序是色觉安全机制，不是装饰。** 这八个色相的排序，保证的是**相邻**槽位在红绿色盲下仍然可分；跳着取、或者挑一个你喜欢的开头，这条保证就没了。按 1、2、3……依次取。

**没有第 9 个颜色。** 第 9 条系列归入「其他」，或者整张图改成小倍数图。绝不自己造一个色相——造出来的在色觉缺陷下与某个既有槽位无法区分，而且它也跟不了主题。

**顺序色是安全的缺省。** 单色相，越多离底色越远。只有当系列本身就是主题时才动用分类色——而当故事是「这一条动了」，那是**强调**（一个槽位，其余用 `--theme-text-tertiary`），不是八个颜色。

**部分槽位对部分主题底色低于 3:1。** 那是色板为色觉可分性付的账，而代价是**图的每一部分都必须直接标注**。靠颜色单独区分各部分的图在这里是错的，无论它在你当前主题下看着多好。

## 只对手写 SVG 成立的几件事

- **你量不了文字。** 没有任何东西告诉你一个标注渲染出来有多宽，所以塞进柱子里的标注是一次押注，迟早会被裁掉。标注放在标记外面。非要估算时，西文按每字符约 0.6em、中日韩按每字 1em 打底，然后再留出余量。
- **没有任何东西替你排版。** 每一个坐标都是你自己定的，所以碰撞是缺省的失败方式。按网格干活——固定的左侧栏放行标签、固定的基线、均匀的间距——并把数量压到网格能保持粗疏。
- **`viewBox` 就是整个坐标系。** 取整数，缩放交给卡片。别去追像素尺寸；`0 0 320 180` 比 `0 0 1024 576` 好摆得多，渲染出来一模一样。
- **给图一个无障碍名字**：根节点上写 `role="img"` 加 `aria-label`，说清这张图给的是什么。应用也正是从这里读回标题。
