# 选图型

这一步排在颜色**之前**，而且判据来自数据的职责，不是哪种图好看。有时正确的形态不是图表，有时根本就不该有图。

## 这件事该不该画成图

只有当**图形本身**承载了散文或表格给不出的论证时，图才挣到了自己的位置。读者从一句话里能更快拿到，那就写那句话。

| 数据是…… | 用 | 别用 |
|---|---|---|
| 一个当前值，也许带个方向 | 就把数字写进句子里 | 一根柱子的柱状图 |
| 几个头条数字 | 一张小表，或散文 | 分组柱状图 |
| 一个比例对一条上限 | 一根柱子加一条上限标记 | 两瓣的饼图 |
| 超过约 7 个都带含义的类别 | 表格 | 更多颜色 |
| 读者要逐位比对的精确数值 | 表格 | 任何图表 |

图表是给**形状**看的——次序、比例、趋势、离群。表格是给**数值**看的。两样都要时，让图表出形状，再点名那两三个真正要紧的数。

## 职责 → 形态

| 读者要做的事 | 形态 | 颜色职责 |
|---|---|---|
| 比较量级，小 → 大 | 横向柱，排好序 | 顺序色，或单个槽位 |
| 跟一条随时间的趋势 | 折线；只有单系列时才用面积 | 单个槽位 |
| 分辨几条不同的系列 | 分组/堆叠柱、多折线 | 分类色 |
| 看出**某一条**才是重点 | **强调**：一个槽位，其余 `--theme-text-tertiary` | 单槽位 + 灰 |
| 基准线上下、与目标的差 | 从居中轴向两侧的双向柱 | 极性 |
| 部分与整体 | 一根横向堆叠柱 | 分类色 |
| 每一项的前 → 后 | 哑铃图（两个点 + 连接线） | 同色相两级 |
| 结构、流程、状态机 | 那是**示意图**——在回复里写 ```mermaid 围栏，聊天会渲染；只值一句话就手画框和箭头 | — |

## 表格背后的道理

- **带名字的东西，横向柱优于纵向柱。** 类别标签不用旋转就能读，长名字放得下，而且可以按值排序——那通常才是真正的重点。
- **除非次序本身有含义，否则就排序。** 按字母或按到达顺序摆，会把读者要来看的排名藏起来。只有时间轴、或本身有序的量表，才保留数据自己的次序。
- **强调是最被低估的形态。** 一条用 `--viz-1`，其余全部 `--theme-text-tertiary`。当故事是「这一条动了」，八个颜色会把它埋掉。这一条极其经常就是「把这张图弄清楚点」的老实答案。
- **柱子从零开始。** 柱形编码的是长度，起点不为零会放大每一处差异——那是最老的图表谎言。随时间的折线可以截断，但要在轴上写明。
- **面积图只给单系列。** 堆叠面积会让第一层以上的每一条都读不出来，因为它们各自的基线都在动。

## 系列数阶梯

| 系列数 | 处理 |
|---|---|
| 1 | 不要图例——标题已经说了画的是什么 |
| 2–3 | 舒服；逐条直接标注 |
| 4 | 直接标注变成强制——黄和橙现在同时在屏幕上了 |
| 5–6 | 软上限；考虑改成小倍数图 |
| 7–8 | 天花板，而且一定显得挤 |
| 9+ | 尾部归入「其他」，或者拆成小倍数图 |

绝不用「再造一个色相」来解决「系列太多」。

## 当它是示意图而不是图表

框和箭头有自己的纪律：**一个**流向（流水线左到右，判定自上而下）、框按网格摆且等宽、箭头接在框的边上而不是角上、只要重排能避免就不要有交叉线。控制在约 10 个框以内——再多就没人读了，而内容本身是在提示你该换一个切法。
