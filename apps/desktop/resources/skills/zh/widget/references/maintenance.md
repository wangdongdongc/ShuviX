# 修改已有的小组件

## 找到它

- `shuvix widget list` 给出 id 和 `projectDir`。如果它只出现在 `--archived` 下，停下来，告诉用户从「Widget 面板」恢复它。
- 如果两个列表里都没有它，但它的目录存在，说明它的 `widget.json` 缺失或损坏：如实汇报，不要去修。
- 请求对得上不止一个小组件（widget）时，问用户指的是哪个。

## 第一次编辑之前

运行 `shuvix widget build <id> --message "chore: baseline before <task>"`：

- 它告诉你这个小组件按现状能否构建，这样你不会替一个本来就存在的故障背锅；
- 它给本次对话访问小组件目录的权限；
- 构建成功时，它把目录里已有的东西提交掉（用户自己的编辑、之前某个会话做了一半的工作），让你的改动落成一个独立的提交。早于版本管理的小组件会在这里得到它的仓库。

如果这次构建失败，就什么都不会提交，说明小组件本来就是坏的。只有用户要求修、或者不修你的改动就落不下来时，修它才是任务的一部分；否则就说明这一点。

然后读 `README.md` 和你要改的每一个文件，遵循它们的约定：命名、文件布局、状态怎么保存。

## 做改动

- 有针对性的 `edit`，不要重写。保留挂载块和它的 "DO NOT DELETE" 注释。
- 表的改动遵循 `data.md`（「修改表」）。
- 在 README 的更新日志里加一行，用 README 的语言。
- `shuvix widget build <id> --message "<what changed>"`，然后 `shuvix widget open <id>`。

## 本技能出现之前写的小组件

旧的小组件是一个已经不存在的内置 Widget Builder 智能体写的，其中一些用了在从浏览器打开 ShuviX 时会坏掉的东西。用户要求更新这样的小组件，或者你的改动碰到这些部分时，把它们改到合规。先在小组件的 `.ts` / `.tsx` 文件里搜索这个模式：

```
shuvix-media:|file://|127\.0\.0\.1|localhost:|localStorage|sessionStorage|indexedDB|document\.cookie
```

| 找到的                                                                | 改成                                                                                                                       |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `shuvix-media:///abs/path`（或构造成 `` `shuvix-media://${p}` ``）    | 来自同一个 URL 模块（`files.md`）的 `fileUrl('/abs/path')` / `fileUrl(p)`；里面的路径是 `shuvix-media://` 之后的部分，解码后使用 |
| `file:///…`                                                           | 同样的 `fileUrl(…)`                                                                                                        |
| `http://127.0.0.1:<port>/w/<id>/…` 或 `localhost:<port>`              | 只留路径：`/w/<id>/…`                                                                                                      |
| `localStorage` / `sessionStorage` / `IndexedDB` / cookie              | 小组件数据库里的一张表（`data.md`）。没有要迁移的东西：小组件地址的端口在每次 ShuviX 启动时都会变，所以浏览器存储从来没活过一次重启 |
| README 里说设计规矩在 Widget Builder 智能体里的那一行                 | 改成一行说它们在内置技能 `builtin:widget` 里                                                                               |

硬编码的主文件夹（`/Users/<name>/…`）可以保留，但 `~/…` 更好（`files.md`）。

旧的小组件也早于主屏：大多数没有 `icon.svg`，很多是按独立窗口的大小排版的。更新这样的小组件时，给它画一个图标，并检查它从 320px 宽起是否能用（`design.md` 的「图标」和「宽度」）。

改完之后构建、打开，并告诉用户你转换了什么，好让他们也从浏览器检查一下这个小组件。
