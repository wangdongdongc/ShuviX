# `widget` 工具

因为你持有本技能，你才有这个工具。它负责造小组件、改小组件，不负责使用：小组件在一条会话里开启后，它的操作就是普通工具，工具名是 `mcp__widget-<id>__<op>`。Id 是小写 ASCII kebab-case，至少带一个连字符；其他一概拒绝。

| 动作      | 参数                                           | 作用                                                                                                                                                         |
| --------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `list`    |                                                | 所有小组件（widget）：id、名称、描述、它的文件夹、它的操作（名称、读 / 写、第一句话），以及本次对话能对它做什么（`none` / `read` / `read-write`）。旧的小组件显示 `storage="legacy-postgres"`；已经换成 SQLite、旧数据还留着的显示 `old-data="legacy-postgres"`（`sql` 带 `legacy: true` 读得到）。 |
| `create`  | `widget`（新的 id）、`name`、`description`     | 为新小组件搭好脚手架并运行它的第一次构建。返回它的文件夹、它的文件和这次构建的结果。                                                                         |
| `build`   | `widget`、`message`                            | 构建界面和 API。返回错误，或者现在生效的操作、警告和提交。构建失败不会改动任何正在运行的东西。                                                               |
| `test`    | `widget`、`op`、`args`                         | 试跑一个操作。调用真的会运行，它写入的一切事后都会回滚；只供界面使用的操作也能试。 |
| `preview` | `widget`、`sizes`、`theme`、`wait_for`         | 界面在 `panel`、`window` 和 `phone`（缺省三种都截）、`light` 或 `dark`（缺省跟应用）下的截图，以图片形式放在结果里，外加页面报出的错误。屏幕上什么都不会打开。`wait_for` 是要先等它出现的 CSS 选择器（最多 30 秒）。 |
| `sql`     | `widget`、`sql`、`legacy`                      | 在小组件的数据库上运行 SQL：建表和改表、查看行、修数据。多条语句的脚本在一个事务里运行。`legacy: true` 让它运行在旧小组件放在共享 PostgreSQL 数据库里的数据上。 |
| `export`  | `widget`、`path`                               | 把一个独立的 Vite 项目打包成一个 .zip（`export.md`）。                                                                                                       |
| `open`    | `widget`                                       | 在运行 ShuviX 的那台电脑上用它自己的窗口打开它。只在用户要你打开时用。                                                                                       |

## 要紧的细节

- **权限**：使用一个小组件需要用户给本次对话的许可，读（试跑读操作、`preview`、`export`）或读写（试跑写操作、`build`、`sql`），第一次时用户在一张卡片上回答。你 `create` 的小组件对本次对话已经是读写。读写还允许你编辑它的文件夹；没有它，在那里写入会先询问。如果用户拒绝，不要另找别的途径进去。
- **真实数据**：`test` 总是回滚。示例数据用 `sql` 写进去。要真正调用一个操作（用户要你这么做时），用 `tool_search` 开启这个小组件：会问用户，之后这条会话读不再问，写第一次还会问。
- **已开启小组件的会话里的新操作**：它的工具在开启时就定下了，之后的构建新加的操作要等 agent 重建才够得到（点 agent 芯片上的 X，或取消再勾上）。`test` 看到的永远是当前的构建。
- **构建失败**是正常、可恢复的结果：修好它报出的问题再构建。
- **提交**：绿色构建之后 ShuviX 会提交整个小组件文件夹，删除也算在内。`message` 是这次提交的标题（缺省 `chore(<id>): build`）；写改了什么，一行。你从不运行 git，也从不碰 `.git`。
- **只有构建过的 API 才生效**：编辑 `api.ts` 在 `build` 成功之前什么都不会改变，所以界面和 API 总是一起变。
- **`sql`** 要过一道词法检查：`ATTACH`、`DETACH`、`VACUUM`、`PRAGMA` 和 `load_extension` 会被拒绝（`data.md`）。不要在脚本里写 `BEGIN` / `COMMIT`；整个脚本本来就是一个事务。
- **`open`** 在 ShuviX 运行的那台电脑上显示窗口。用户在 ShuviX 的网页上，或者 ShuviX 以无界面（headless）方式运行（此时 `open` 会失败）时，告诉用户改从「Widget 面板」打开小组件；在那里它会在新的浏览器标签页里打开。
- **shell**：已经没有 `shuvix widget` 命令了，小组件的路由也拒绝来自你 shell 的请求。用 `test` 测试操作，用 `sql` 查看数据，用 `preview` 查看界面。
